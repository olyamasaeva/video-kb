# video-kb — правила для агентов

Репозиторий скилла Claude Code `video-kb`: `SKILL.md` (промпт) и `scripts/` (пять
независимых скриптов). Установленная копия `~/.claude/skills/video-kb` — симлинк сюда,
поэтому правка в `main` сразу меняет поведение скилла.

- **Контракт поведения — `openspec/specs/`.** Требование = ID = тест с
  `@pytest.mark.contract("ID")`, связь сторожит `tests/test_openspec_contract.py`.
  Изменение поведения скриптов — через `openspec/changes/` и скиллы `openspec-*`:
  сначала падающий тест, потом код; архивировать только при зелёном `uv run pytest` и
  `openspec validate --specs --strict`. ID не переиспользуются и не перенумеровываются.
- **Скрипты — только стандартная библиотека**, вызываются по пути
  (`python3 scripts/<имя>.py …`). Новая зависимость, пакет или общий модуль — только с
  одобрения автора (`notes/не-код.md`, «Когда вернуться»).
- **В отслеживаемых файлах нет личного контекста автора и реальных баз знаний.**
  Общие маркеры (домашние пути, e-mail, id чатов) сторожит
  `tests/test_no_personal_context.py`; личные строки автора — локальный хук
  `private-denylist` (`hooks/denylist.py`) по списку `~/.config/video-kb/denylist.txt`
  вне репозитория. Новую личную строку дописывать в этот список, а не в тест. Примеры
  синтетические (курс
  `example-course`, пути `~/kb/<курс>`). Тесты строят входы в
  `tmp_path` и запускают скрипты подпроцессом.
- **Комментариев в `.py` нет** (хук `no-comments`): смысл — в именах и докстрингах.
- Требования, помеченные «похоже на дефект», описывают текущее поведение. Чинить —
  отдельным изменением OpenSpec с MODIFIED-требованием, а не тихой правкой скрипта.
- Python — только через `uv run`; тесты — `uv run pytest` из корня.
