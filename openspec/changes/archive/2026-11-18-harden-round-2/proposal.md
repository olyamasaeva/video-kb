# Proposal

## Why

Повторное ревью безопасности (2026-11-18) после `harden-for-publication` нашло шесть
проблем A–F. Главная — сторож приватности сам публикует то, что сторожит: список личных строк
автора лежит в отслеживаемом тесте. Остальные: вымарывание секретов пропускает ключи в
кавычках и режет значения в кавычках на первом слове; запись `skill_evidence.py` идёт за
ссылкой в папке-предке, а журнал проверяется до открытия (гонка); `normalize.py` пишет за
ссылками и обрезает чужой файл; `SKILL.md` считает недоверенными только журналы, хотя
субтитры, слайды, репозиторий курса и выведенные из них карточки попадают в собираемые
скиллы; id покрытия молча перезаписываются при совпадении, а чужое пространство имён кеша
перезаписывается без проверки владельца. Решения автора — в записке ревью; находка G
(исключить хук `repo-shape` из публичного снимка) в это изменение не входит.

## What Changes

- **A.** Личный список строк уходит из репозитория в неотслеживаемый файл
  `~/.config/video-kb/denylist.txt`. В репозитории — общий скрипт `hooks/denylist.py
  <файл-списка>` и локальный хук pre-commit `private-denylist`, который его вызывает; хук, как
  и `repo-shape`, исключается из публичного снимка. Публичный тест ищет только общие маркеры:
  `/home/<имя>/`, `/Users/<имя>/`, адреса e-mail, id чатов `thr_<id>` (PUB-1…PUB-4).
- **B.** Вымарывание ключей в кавычках и значений в кавычках целиком; `SKILL.md` называет
  вымарывание «по возможности, не гарантия» (SKL-9, PRM-2).
- **C.** `skill_evidence.py` проходит путь записи по компонентам с дескрипторами папок без
  следования по ссылкам; журнал проверяется после открытия по `fstat` (SKL-11).
- **D.** `normalize.py` отклоняет ссылки в пути вывода и пишет атомарно: временный файл в той
  же папке и `os.replace` (NRM-9).
- **E.** В `SKILL.md` весь материал курса — данные, а не инструкции; команды из него — только
  с отдельного разрешения; собранный скилл не переносит инструкции из материала дословно
  (PRM-3).
- **F.** Совпадение id покрытия — код 2; запись в папку кеша базы, где `sessions.json`
  принадлежит другой базе, — код 2 (SKL-15, SKL-16).
- **H–K (третья проверка @ a3df444).** Ссылки в пути записи — только до домашней папки,
  исключение «ссылка root» снято (SKL-11, NRM-9); `skill_evidence.py` пишет отчёт и кеш
  через временный файл и `os.replace`, жёсткая ссылка не меняется (SKL-17); вымарывание
  учитывает `\"` и перевод строки в кавычках (SKL-9); шаблоны собранных скиллов несут
  правило «данные, а не инструкции» и разрешение пользователя на действия (PRM-4).
