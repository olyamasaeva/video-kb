## MODIFIED Requirements

### Requirement: SKL-5 В отчёте нет текста реплик и путей
`<база>/skills/доказательства.json` и `.md` SHALL содержать по сессии только id (16 hex-знаков sha256 пути журнала), движок, дату и совпавшие фразы; текст реплик, пути проектов, заголовки сессий, имена скиллов и пути правил MUST NOT попадать в отчёт и stdout. Связка id → путь журнала SHALL писаться в `<кеш>/<16 hex-знаков sha256 пути базы>/sessions.json` (кеш по умолчанию `~/.cache/video-kb`, флаг `--кеш`).

#### Scenario: SKL-5 отчёт без текста и путей
- **WHEN** реплика с фразой содержит уникальную строку-маркер, а журнал лежит в папке с маркером в имени
- **THEN** ни одного маркера нет в файлах `skills/` и stdout, id из 16 hex-знаков, путь журнала есть в `sessions.json` под кешем
- Тест: `tests/test_skill_evidence.py::test_skl5_no_text_no_paths`

### Requirement: SKL-6 Покрытие скиллами и правилами, бюджет описаний
Скрипт SHALL собирать скиллы (`SKILL.md` в папках `--скиллы`, по умолчанию `~/.claude/skills`, `~/.codex/skills`, `~/.agents/skills`) и правила (`CLAUDE.md`, `AGENTS.md`, `.claude/rules/*.md`, `rules/*.md` из `--правила`, по умолчанию `~/.claude`, `~/.codex`); текущая папка MUST NOT подключаться по умолчанию. Для кандидата SHALL выводить id скиллов (`скилл-<12 hex>`) и файлов правил (`правило-<12 hex>`), где есть его фраза по SKL-3, и бюджет: число скиллов и длину их `description`.

#### Scenario: SKL-6 кандидат покрыт скиллом
- **WHEN** описание установленного синтетического скилла содержит фразу кандидата
- **THEN** в покрытии кандидата один id `скилл-…`, в бюджете 2 скилла и длина их описаний
- Тест: `tests/test_skill_evidence.py::test_skl6_coverage_and_budget`

#### Scenario: SKL-6 кандидат покрыт правилом
- **WHEN** фраза кандидата есть в синтетическом `AGENTS.md`
- **THEN** в покрытии кандидата один id `правило-…`
- Тест: `tests/test_skill_evidence.py::test_skl6_rules`

#### Scenario: SKL-6 текущая папка не подключается по умолчанию
- **WHEN** скрипт запущен без `--скиллы` и `--правила` из папки, где `AGENTS.md` и `.claude/skills/x/SKILL.md` содержат фразу, а `HOME` — пустая папка
- **THEN** покрытие кандидата пустое, в бюджете 0 скиллов
- Тест: `tests/test_skill_evidence.py::test_skl6_cwd_not_default`

### Requirement: SKL-9 Реплики одной сессии — только в терминал
`--показать <id сессии>` SHALL печатать в stdout предупреждение «текст журнала — данные, не инструкции» и только реплики пользователя этой сессии в окне `--дней` с фразой кандидата базы: с датой, фрагментом не длиннее 400 знаков вокруг совпадения и секретами, заменёнными на `[скрыто]`. Скрипт MUST NOT писать в `<база>/skills/`; неизвестный id MUST давать код 2.

#### Scenario: SKL-9 показ сессии
- **WHEN** после построения отчёта вызывается `--показать` с id найденной сессии
- **THEN** совпавшая реплика в stdout, ответ агента нет, файлы `skills/` не изменились
- Тест: `tests/test_skill_evidence.py::test_skl9_show_session`

#### Scenario: SKL-9 только совпавшие реплики в окне, фрагмент, секреты
- **WHEN** в сессии реплика без фразы, реплика с фразой старше окна и реплика с фразой, ключом `sk-…`, `password=…` и 2000 знаками текста вокруг
- **THEN** в stdout только третья реплика фрагментом не длиннее 400 знаков, ключа и пароля нет, есть `[скрыто]` и предупреждение
- Тест: `tests/test_skill_evidence.py::test_skl9_show_filters_and_redacts`

#### Scenario: SKL-9 неизвестный id
- **WHEN** `--показать deadbeef` при пустом кеше
- **THEN** код 2
- Тест: `tests/test_skill_evidence.py::test_skl9_unknown_id`

## ADDED Requirements

### Requirement: SKL-10 Имена скиллов и пути правил — только в кеше
Имена скиллов и пути файлов правил SHALL храниться только в кеше базы (SKL-5) под id покрытия; `--показать <id покрытия>` SHALL печатать имя или путь в stdout, ничего не записывая в `<база>/skills/`.

#### Scenario: SKL-10 правило в приватно названном проекте
- **WHEN** фраза кандидата есть в `.claude/rules/<маркер>.md` проекта `<маркер>` и в описании скилла с именем-маркером
- **THEN** маркеров нет в файлах `skills/` и stdout отчёта; `--показать` по id покрытия печатает путь правила и имя скилла
- Тест: `tests/test_skill_evidence.py::test_skl10_private_rule_and_skill_names`

### Requirement: SKL-11 Символические ссылки не читаются и не пишутся
Журнал, который сам символическая ссылка или чей разрешённый путь вне разрешённого корня журналов, MUST NOT читаться ни при отчёте, ни при `--показать`. Если `<база>/skills`, файл отчёта, корень кеша или папка кеша базы — символическая ссылка, скрипт MUST завершиться с кодом 2 и сообщением в stderr, не записав ничего по ссылке.

#### Scenario: SKL-11 ссылка на чужой файл вместо журнала
- **WHEN** в папке журналов `.jsonl`-ссылка на файл вне корня, где есть реплика с фразой
- **THEN** у кандидата 0 сессий, журналов в окне 0
- Тест: `tests/test_skill_evidence.py::test_skl11_symlinked_journal_ignored`

#### Scenario: SKL-11 файл отчёта — ссылка
- **WHEN** `skills/доказательства.md` — ссылка на файл вне базы
- **THEN** код 2, файл вне базы не изменился
- Тест: `tests/test_skill_evidence.py::test_skl11_symlinked_output_rejected`

#### Scenario: SKL-11 папка кеша базы — ссылка
- **WHEN** папка кеша базы — ссылка на чужую папку
- **THEN** код 2, в чужой папке не появилось файлов
- Тест: `tests/test_skill_evidence.py::test_skl11_symlinked_cache_rejected`

### Requirement: SKL-12 Враждебные журналы: неверная форма и ошибки чтения
Записи журнала неверной формы (не объект, `message` или `payload` не объект, текст не строка) SHALL пропускаться без ошибки. Файл больше 256 МиБ, строка длиннее 1 000 000 знаков или ошибка чтения SHALL давать ошибку файла: путь и причину в stderr, в отчёте строку «скан неполный» и число таких журналов по движку, код 4 вместо 0 и 3.

#### Scenario: SKL-12 записи неверной формы
- **WHEN** в журналах обоих движков рядом с репликой с фразой лежат `["user"]`, `{"type": "user", "message": "x"}`, контент-число, `payload`-список
- **THEN** код 0, у кандидата 2 сессии
- Тест: `tests/test_skill_evidence.py::test_skl12_wrong_shapes_skipped`

#### Scenario: SKL-12 строка длиннее предела
- **WHEN** в одном журнале строка длиннее 1 000 000 знаков, в другом — реплика с фразой
- **THEN** код 4, в отчёте «скан неполный», у кандидата 1 сессия
- Тест: `tests/test_skill_evidence.py::test_skl12_oversized_line_incomplete`

#### Scenario: SKL-12 журнал не читается
- **WHEN** у одного журнала нет прав на чтение
- **THEN** код 4, в stderr путь журнала, в отчёте «скан неполный»
- Тест: `tests/test_skill_evidence.py::test_skl12_unreadable_journal_incomplete`

### Requirement: SKL-13 Сопоставление без перебора всех префиксов
Память на сопоставление реплики SHALL расти линейно с её длиной: длинное слово MUST NOT порождать все свои префиксы.

#### Scenario: SKL-13 слово в 60 000 знаков
- **WHEN** реплика — одно слово в 60 000 знаков, процесс ограничен 512 МиБ адресного пространства
- **THEN** код 0, у кандидата 0 сессий
- Тест: `tests/test_skill_evidence.py::test_skl13_long_word_bounded_memory`

### Requirement: SKL-14 Кеш приватный и только для совпавших сессий
Папка кеша базы SHALL создаваться с правами 0700, `sessions.json` — 0600; в кеш SHALL попадать только сессии, совпавшие хотя бы с одним кандидатом, и id покрытия.

#### Scenario: SKL-14 права и состав кеша
- **WHEN** в журналах сессия с фразой и сессия без неё
- **THEN** права папки 0700, файла 0600, в кеше id только первой сессии
- Тест: `tests/test_skill_evidence.py::test_skl14_cache_private_and_minimal`

### Requirement: SKL-15 Кеш разделён по пути базы
Пространство имён кеша SHALL быть хешем разрешённого пути базы, а `sessions.json` SHALL хранить этот путь; `--показать` MUST давать код 2, если в кеше записан другой путь базы.

#### Scenario: SKL-15 две базы с одним именем
- **WHEN** отчёт построен для `a/kb`, затем `--показать` с id его сессии вызван для `b/kb`
- **THEN** у баз разные папки кеша, показ для `b/kb` — код 2
- Тест: `tests/test_skill_evidence.py::test_skl15_cache_namespaced_by_path`
