# video-kb: режим `skills` — дизайн

Дата: 2026-11-17. Подход одобрен автором 2026-11-17; требования — в specs/skills/spec.md этого изменения.

## Зачем

`video-kb` превращает плейлист курса в базу знаний: нормализованные транскрипты,
конспекты с таймкодами, карточки практик с «Границами», словарь. Новый режим отвечает
на следующий вопрос: **нужны ли из этой базы скиллы для агента**, и собирает их после
«да» пользователя. Инструмент будет опубликован, поэтому режим работает у любого
пользователя Claude Code или Codex, а не только на машине автора.

Главное требование автора: режим **проверяет, действительно ли скиллы нужны**. Вердикт
«скилл не нужен, хватит карточек» — штатный и ожидаемый исход. Скиллов уже много, и
описания вытесняют друг друга: по замерам из t.me/llm_under_hood (/960, /988) Claude Code
отводит описаниям около 1% окна, остальные видны только по имени.

## Цели, не-цели, анти-цели

**Цели**
- Отчёт о нужности: кандидаты в скиллы с доказательствами из работы пользователя и
  вердиктом по каждому.
- Сборка одобренных скиллов, которые ссылаются на карточки базы, а не копируют их.
- Вариант по умолчанию, когда ни один кандидат не прошёл: один скилл-указатель на базу.

**Не-цели**
- Публикация самого `video-kb` (отдельный репозиторий, плагин, английская версия) —
  следующий этап, свой дизайн. Здесь только ограничения переносимости, см. ниже.
- Автоматическое обновление скиллов при изменении базы.
- Оценка качества самих карточек.

**Анти-цели** (провал, даже если всё работает)
- Режим предлагает скилл на каждую тему курса: это пересказ курса, а не проверка нужности.
- Скилл дублирует уже установленный скилл или правило пользователя.
- Отчёт выносит наружу содержимое журналов сессий: в журналах бывают ключи и личное.

## Ограничения

- Только стандартная библиотека Python 3.10+, как у остальных скриптов `video-kb`.
- Без сети и без LLM-вызовов из скриптов: смысловую работу делает агент, который ведёт
  режим, скрипты только считают.
- Ни одного личного пути и личных имён; журналы и папки скиллов ищутся в стандартных
  местах с возможностью переопределить флагом.
- Ничего не пишется в папки скиллов без явного «да» на конкретный скилл.

## Подходы

1. **Сначала доказательства — выбран.** Скрипт ищет в журналах сессий пользователя
   ситуации, где карточки были бы применимы, и сверяет с установленными скиллами. Нет
   журналов — спрашивает, для какой работы курс. Плюс: решение опирается на факты и
   воспроизводимо. Минус: поиск по журналам грубый, кандидатов агент перечитывает сам.
2. **Сначала пробное использование.** Ставится скилл-указатель, журнал открытых карточек
   за несколько недель решает, что выделять. Самое честное, но результат через недели и
   нужно хранилище журнала. Из него взят только скилл-указатель как вариант по умолчанию.
3. **Мнение агента по интервью.** Просто, но нужность утверждается, а не проверяется —
   нарушает главное требование.

Автор выбрал первый с указателем по умолчанию (2026-11-17).

## Как устроено

### Поток

1. **Кандидаты.** Агент группирует карточки базы в кандидатов. Отправная точка — темы
   (`practices/<тема>/`), но кандидат — это **повторяемое действие** с поводом к запуску
   («проектирую цикл агента», «пишу eval для агента»), а не тема лекции. Карточки без
   действия (чистое знание) в кандидаты не идут. Результат — `skills/кандидаты.tsv`:
   имя кандидата, карточки, одной строкой — когда срабатывает.
2. **Запросы ситуаций.** Для каждого кандидата агент пишет 5–15 поисковых фраз о том,
   как такая ситуация звучит в запросах пользователя, **на языках пользователя**
   (курс может быть английским, а пользователь пишет по-русски). Файл
   `skills/запросы.tsv`: кандидат, фраза. Это главный ручной шаг, его качество решает всё.
3. **Доказательства — скрипт `skill_evidence.py`.** Читает реплики пользователя (только
   их, не ответы агента и не вывод инструментов) из журналов Claude Code
   (`~/.claude/projects/*/*.jsonl`) и Codex (`~/.codex/sessions/**/*.jsonl`) за окно
   (по умолчанию 60 дней, `--дней`), ищет фразы из `запросы.tsv` (без учёта регистра,
   по леммоподобной основе: обрезка окончаний до общего префикса, без внешних
   библиотек). Для каждого кандидата выводит: число сессий с совпадением, дни, проект
   (папку), заголовок сессии, совпавшие фразы. **Текст реплик в отчёт не попадает**,
   только идентификаторы и совпавшие фразы; `--показать <сессия>` печатает реплики
   одной сессии в терминал для проверки агентом.
4. **Покрытие.** Тот же скрипт собирает установленные скиллы: `~/.claude/skills/*/SKILL.md`,
   `.claude/skills/` текущего проекта, `~/.codex/skills/`, `~/.agents/skills/`, кеш
   плагинов Claude Code. Для каждого кандидата — скиллы с пересечением по фразам
   запросов и по словам описания. Плюс общий бюджет: число скиллов и суммарная длина
   описаний.
5. **Вердикт — агент**, по правилам:
   - **нужен**: совпадения в ≥ 2 разных сессиях за окно (порог `--мин-сессий`), агент
     прочитал эти сессии и подтвердил, что ситуация та; действие не покрыто скиллом;
     в карточках многошаговое «Как» или в найденных сессиях пользователь поправлял агента
     по этой теме;
   - **дописать существующий**: ситуация есть, но покрыта установленным скиллом — предложение
     правки того скилла, а не нового;
   - **хватит карточек**: ситуации нет или она одношаговая.
   Нет журналов вообще (новый пользователь) — режим спрашивает, для какой работы курс,
   и выносит вердикт «заявлено, не подтверждено» с той же логикой, но не выше
   «нужен условно».
6. **Отчёт** `skills/ПРОВЕРКА.md` в корне базы: таблица кандидат → сессии (число, даты) →
   покрытие → вердикт → почему; строка бюджета («установлено N скиллов, описания X знаков,
   каждый новый добавит ~Y»). Агент показывает отчёт и спрашивает, какие собирать.
7. **Сборка** — только названные пользователем. На скилл: папка `<имя>/SKILL.md` в
   выбранном месте (по умолчанию `~/.claude/skills/`, вариант — `.claude/skills/` проекта),
   frontmatter `name` + `description` с поводами к запуску словами пользователя из
   найденных сессий, тело — шаги действия со ссылками на карточки базы абсолютными путями
   и таймкодами. Проверка frontmatter скриптом. В README базы — строка «скиллы из базы».
8. **Указатель по умолчанию.** Если ни один кандидат не «нужен», режим предлагает один
   скилл `<курс>-kb`: описание называет темы курса, тело говорит, где README, словарь и
   карточки. Тоже только после «да».

### Новые файлы скилла

- `scripts/skill_evidence.py` — шаги 3–4, JSON и markdown на выходе.
- Раздел `## Режим: skills` в `SKILL.md`, вызов `/video-kb skills <путь к базе>`.
- Шаблон `templates/skill.md` для шага 7.

### Приёмка

- На английской базе (будет собрана после режима) и реальных журналах автора
  отчёт строится, тексты реплик в нём отсутствуют, вердикты агент обосновывает по
  прочитанным сессиям.
- На реальной русской базе режим находит, что практики формы репозитория уже покрыты
  установленным скиллом
  (вердикт «дописать существующий» или «хватит карточек»), — проверка, что покрытие
  работает.
- На пустых журналах (`--журналы` на пустую папку) режим переходит к вопросу о работе.
- Тесты `skill_evidence.py` на синтетических журналах обоих форматов.

## Решения, принятые мной (проверьте)

- Поиск лексический по фразам, которые пишет агент, а не эмбеддинги: стандартная
  библиотека, без сети, и межъязыковость закрывается тем, что агент пишет фразы на языке
  пользователя.
- Окно 60 дней и порог 2 сессии — по умолчанию, меняются флагами.
- Скиллы ссылаются на карточки, а не копируют их: база остаётся единственным источником.

## Решения после проверки сборщиком (мои, проверьте)

- **Сессии сборки самой базы не считаются доказательством.** `skill_evidence.py` по умолчанию
  исключает сессии, у которых рабочая папка внутри базы или где вызывался `video-kb`
  (`--включить-сборку` отключает фильтр). Иначе любой курс «нужен» целиком.
- **«Дописать существующий» — только предложение текстом** в `ПРОВЕРКА.md`: какой скилл и
  какую строку добавить. Режим не пишет в чужие `SKILL.md`, тем более в кеш плагинов.
- **Покрытие проверяется и по правилам:** `CLAUDE.md`, `AGENTS.md`, `.claude/rules/` —
  глобальные (`~/.claude/`, `~/.codex/AGENTS.md`) и текущего проекта. Вердикт
  «уже в правилах» — разновидность «хватит карточек».
- **В `ПРОВЕРКА.md` нет путей проектов и заголовков сессий**, только короткие id сессий
  (8 знаков хеша), даты и совпавшие фразы. Связка id → файл журнала пишется локально в
  `~/.cache/video-kb/<база>/sessions.json`, не в базу.
- **Порядок приёмки:** сначала синтетические журналы обоих форматов и реальная русская
  база; английская база — вторая приёмка, когда будет собрана.
- **Место сборки скилла** — спросить у пользователя, по умолчанию папка того движка, в
  котором идёт режим (`~/.claude/skills/` или `~/.agents/skills/` для Codex); frontmatter
  одинаковый (`name`, `description`) — его понимают оба.
- **Окно журналов:** по умолчанию 60 дней, в отчёте — сколько дней журналов реально
  нашлось по каждому движку (Claude Code по умолчанию чистит журналы старше 30 дней, у
  Codex журналы живут дольше).

## Оставлено исполнителю

Формат JSON `skill_evidence.py`, точный алгоритм основы слова, разбор форматов журналов
(взять за образец существующий разборщик журналов), тексты шаблона.
